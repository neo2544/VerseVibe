# VerseVibe UX 개선 계획

> 작성일: 2026-02-10
> 상태: 계획됨

사용자 관점에서 발견된 9가지 개선점을 정리하고, 우선순위별로 하나씩 구현한다.

---

## 개선 #1: 잘못된 곡 재인식 방지 [높음]

**현상:** 가사를 정상적으로 보고 있다가 갑자기 다른 곡으로 인식되어 엉뚱한 가사가 표시됨.

**원인:**
- `main.py` process_loop에서 20초마다 Shazam 재호출
- 인식 결과가 다른 곡이면 아무 검증 없이 즉시 가사 교체
- 신뢰도 체크, 연속 인식 확인, 곡 고정 기능 모두 없음

**개선 방안:**
- 곡 전환 시 "연속 2회 동일 곡 인식" 조건 추가 (1회 인식은 후보로만 보관)
- 프론트엔드에 "곡 고정(Lock)" 토글 추가 — 활성화 시 재인식 무시
- 곡 전환 시 사용자에게 확인 UI 표시 ("다른 곡이 감지되었습니다. 전환할까요?")

**관련 파일:** `backend/main.py`, `frontend/app.js`

---

## 개선 #2: 자동 스크롤 + 가사 탐색 [높음]

**현상:** 이전/이후 가사를 보려고 스크롤해도 0.1초 후 현재 가사 위치로 강제 복귀됨.

**원인:**
- `updateCurrentLyric()`이 100ms마다 `scrollToLine()` 호출
- 사용자 스크롤 감지 로직 없음
- 지나간 가사는 opacity 0.35로 거의 안 보임

**개선 방안:**
- 사용자 터치/스크롤 감지 시 자동 스크롤 3~5초 일시정지
- "현재 가사로 돌아가기" 플로팅 버튼 표시 (일시정지 중에만)
- 지나간 가사 opacity를 0.5~0.6으로 상향하여 가독성 확보

**관련 파일:** `frontend/app.js`, `frontend/style.css`

---

## 개선 #3: Whisper 폴백 싱크 문제 [중간]

**현상:** Whisper로 인식 시 가사가 항상 처음(0초)부터 시작되어 싱크가 완전히 어긋남.

**원인:**
- `lyrics_matcher.py:252`에서 offset을 항상 0.0으로 반환
- Whisper는 "현재 재생 위치"를 알 수 없기 때문

**개선 방안:**
- Whisper 인식 텍스트를 가사 라인과 매칭하여 대략적 offset 추정
- 인식된 텍스트가 가사의 어느 구간에 해당하는지 찾아 해당 타임스탬프를 offset으로 사용
- LRC 파싱된 가사에서 유사도가 가장 높은 구간의 time 값 활용

**관련 파일:** `backend/lyrics_matcher.py`, `backend/lrc_parser.py`

## 개선 #4: 곡 전환 UX [중간]

**현상:** 곡이 바뀔 때 이전 가사가 즉시 사라지고 맥락 없이 새 가사로 대체됨.

**원인:**
- `handleRecognized()`에서 즉시 `renderLyrics()` 호출
- 전환 알림이나 애니메이션 없음

**개선 방안:**
- 곡 전환 시 "새로운 곡이 감지되었습니다" 토스트/배너 표시
- 가사 영역에 fade-out → fade-in 전환 애니메이션 적용
- 개선 #1의 곡 고정 기능과 연계

**관련 파일:** `frontend/app.js`, `frontend/style.css`, `frontend/index.html`

---

## 개선 #5: WebSocket 재연결 [중간]

**현상:** 네트워크 불안정 시 WebSocket이 끊기면 가사가 멈추고 수동으로 재시작해야 함.

**원인:**
- `ws.onerror`에서 바로 에러 화면으로 전환
- 재연결 로직 없음

**개선 방안:**
- WebSocket 끊김 시 자동 재연결 (최대 3회, 지수 백오프)
- 재연결 중에는 가사 화면 유지 + "재연결 중..." 표시
- 재연결 성공 시 현재 곡 상태 복원
- 모든 재연결 실패 시에만 에러 화면 표시

**관련 파일:** `frontend/app.js`

## 개선 #6: 인식 일시정지 (마이크/배터리) [중간]

**현상:** 곡 인식 후에도 마이크 녹음이 20초 주기로 계속 돌아가 배터리 소모 및 프라이버시 우려.

**원인:**
- 가사 표시 후에도 위치 보정을 위해 녹음 사이클이 계속됨
- "중지" 버튼을 누르면 가사 화면 자체가 사라짐

**개선 방안:**
- "인식 일시정지" 버튼 추가 — 마이크 끄고 가사만 계속 표시 (로컬 타이머로 싱크 유지)
- 일시정지 중에도 offset 타이머는 계속 작동
- "재개" 버튼으로 다시 인식 시작 가능
- 일시정지 시 LIVE 배지를 "PAUSED"로 변경

**관련 파일:** `frontend/app.js`, `frontend/index.html`, `frontend/style.css`

## 개선 #7: 가사 표시 품질 [낮음]

**현상들:**
- 간주(instrumental) 구간에서 마지막 가사에 하이라이트가 멈춰 "멈춘 건가?" 혼동
- 곡 진행률을 알 수 없음
- 가사를 못 찾았을 때 할 수 있는 게 없음

**개선 방안:**
- LRC 빈 줄을 "♪ (간주)" 등으로 표시 (lrc_parser.py에서 빈 텍스트도 유지)
- 가사 화면 상단 또는 하단에 얇은 진행률 바 추가
- 가사 없는 경우 "가사 제공 없음 — 곡 정보만 표시합니다" + 곡 정보 강조

**관련 파일:** `backend/lrc_parser.py`, `frontend/app.js`, `frontend/style.css`

---

## 개선 #8: Whisper 언어 자동감지 [낮음]

**현상:** Whisper 언어가 한국어("ko")로 하드코딩되어 영어/일본어 등 다른 언어 노래 인식 불가.

**원인:** `lyrics_matcher.py:39`에서 `language="ko"` 고정

**개선 방안:**
- `language=None`으로 변경하여 Whisper 자동 언어 감지 활용
- 또는 프론트엔드에서 사용자가 언어 선택할 수 있는 옵션 제공

**관련 파일:** `backend/lyrics_matcher.py`

---

## 개선 #9: 히스토리 활용도 [낮음]

**현상:** 히스토리 아이템을 탭해도 아무 반응 없음. 오인식된 곡도 그대로 기록됨.

**개선 방안:**
- 히스토리 아이템 탭 시 가사 다시 보기 (오프라인, 싱크 없이 전체 가사 표시)
- 개별 항목 삭제 (스와이프 또는 삭제 버튼)
- 가사 화면에서도 히스토리 접근 가능하도록

**관련 파일:** `frontend/app.js`, `frontend/index.html`, `frontend/style.css`, `backend/main.py`
